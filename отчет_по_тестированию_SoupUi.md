## 2. Объект тестирования

### 2.1 Базовый URL
http://api.wishlist.otus.kartushin.su

### 2.2 Тестируемые эндпоинты

#### Авторизация и пользователи

| Метод   | Эндпоинт             | Назначение                          |
|---------|----------------------|-------------------------------------|
| `POST`  | `/api/auth/register` | Регистрация нового пользователя     |
| `POST`  | `/api/auth/login`    | Авторизация и получение JWT токена  |
| `GET`   | `/api/users`         | Получение списка всех пользователей |

#### Управление списками желаний (Wishlists)

| Метод    | Эндпоинт                       | Назначение                                   |
|----------|--------------------------------|----------------------------------------------|
| `GET`    | `/api/wishlists`               | Получение всех списков текущего пользователя |
| `GET`    | `/api/wishlists/{id}`          | Получение списка по ID                       |
| `GET`    | `/api/wishlists/user/{userId}` | Получение списков пользователя по ID         |
| `POST`   | `/api/wishlists`               | Создание нового списка желаний               |
| `PUT`    | `/api/wishlists/{id}`          | Обновление данных списка                     |
| `DELETE` | `/api/wishlists/{id}`          | Удаление списка желаний                      |

#### Управление подарками (Gifts)

| Метод    | Эндпоинт                           | Назначение                       |
|----------|------------------------------------|----------------------------------|
| `GET`    | `/api/gifts/wishlist/{wishListId}` | Получение всех подарков в списке |
| `POST`   | `/api/gifts/wishlist/{wishListId}` | Создание нового подарка          |
| `GET`    | `/api/gifts/{id}`                  | Получение подарка по ID          |
| `PUT`    | `/api/gifts/{id}`                  | Обновление данных подарка        |
| `PUT`    | `/api/gifts/{id}/reserve`          | Переключение статуса резерва     |
| `DELETE` | `/api/gifts/{id}`                  | Удаление подарка                 |

### 4.5 Заключение
Проект автоматизированного тестирования API сервиса "Wishlist" в SoupUI имеет следующие особенности:

1. использование идентификатора "id" без возможности локализации в потоке данных для разных сущностей усложнаяет организацию тестирования
2. особенность структуры данных и среды усложняет выстраивание тестов для многопоточного прохождения
3. невозможно сформировать полноценного тестового набора очистки среды, что приводит к ошибкам в моно-потоковом запуске тестов (при том, что по одиночке тесты проходятся успешно)
4. инструмент отчетности о прогоне у SoupUI дает более детальный анализ в сравнении с инструментами встроенными в Postman
